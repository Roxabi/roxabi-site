Three core metaphors — Operating Layer · Compounding Foundations · The Stack Is Yours

These aren't decoration. Each one carries a specific structural claim, and each has its own copy application. Overuse kills the punch — deploy deliberately.

The Operating Layer
Meaning Infrastructure that sits below application logic and above the hardware — like an OS sits below applications. You don't build an OS every time you write a program. You build on the OS. Roxabi is the OS layer for agentic systems. Why it works Positions Roxabi as infrastructure, not a tool. Implies persistence (layer exists before your work starts and after it ends). Implies composability (anything that runs on the layer can use it). Sets the competitive frame correctly — against frameworks and closed platforms, not other tools.
Copy applications
  • "Roxabi is the operating layer for your agentic stack." — positioning, pillars, Constitution (site hero = §1 locked Lead)
  • "The layer that doesn't change between projects." — differentiator context
  • "Start from the operating layer, not before it." — CTA context
  • Avoid: "operating system" (implies more than is correct); "platform" (banned).
Compounding Foundations
Structural meaning Each Roxabi module extends cleanly. Add a new harness, it wires into the existing routing layer. A contributor adds a pattern to the commons — every subsequent builder starts from that position. The dependency graph grows. Value of foundations grows with the graph. Compounding in the same sense as compound interest — structural, not aspirational.
Copy applications
  • "Every piece you add compounds." — factual claim about the module system
  • "Built on what came before. Extended by what comes next." — commons / contribution context
  • "The foundations grow with the people who use them." — community / Constitution context
  • Avoid: "compound" as noun ("the compounding we've created"); motivational energy ("let's compound together").
The Stack Is Yours
Ownership framing "Yours" means: forkable from the first clone, self-hostable on any infrastructure you control, no telemetry by default, no feature gates, no vendor lock-in. The moment you run git clone, the stack is yours. It doesn't require Roxabi's permission, servers, or continued existence to keep working.
Where to deploy
  • Hero taglines and sub-headlines — "Pre-wired. Open. Yours."
  • Nadia's narrative arc — sovereignty as practical survival
  • Anti-SaaS comparison copy — contrasted with "tools you rent"
  • Product descriptions — "Run it on your own infrastructure. Nothing calls home."
  • Avoid: using "yours" where it's not technically accurate (if any managed layer exists).
Usage gate
Compounding is structural, not motivational. Whenever you use the word, ask: can the reader verify it in the dependency graph? If yes, ship it. If the only answer is "because we said so," the sentence is marketing — cut it and describe the mechanism.
