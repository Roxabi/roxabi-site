The character — forked three repos last weekend, debugged it, telling you what happened

Not a startup founder pitching a vision. Not a technical writer sanitizing a doc. A peer who built the thing and is giving you the honest version.

§4.1 · Five voice attributes — this / not-that

1. Peer-to-peer, not broadcast

This "You've probably already built a version of this. The harness exists so you don't have to rebuild it from scratch every time."
Not that "Roxabi empowers developers to build the agentic systems of tomorrow by providing world-class infrastructure."

2. Concrete over aspirational

This "The orchestration layer handles routing between agents, state persistence, and error recovery. You wire it once, then add agents without touching the scaffolding."
Not that "A visionary orchestration framework that transforms how you think about building agentic systems at scale."

3. Honest about trade-offs

This "This approach gives you full control over the agent loop. It also means you own the complexity. If you'd rather abstract that away, the higher-level harness might be a better starting point."
Not that "Roxabi gives you total flexibility with zero added complexity — the best of both worlds."

4. Non-evangelical about open source

This "It's open. Fork it, run it, extend it. If you find something broken or missing, the repo is there."
Not that "We believe in the transformative power of open source to democratize access to AI and liberate developers from proprietary lock-in."

5. Direct about scope

This "Roxabi is infrastructure for solo developers and small teams who build agentic systems. It's not for enterprises with dedicated AI platform teams."
Not that "Roxabi scales from individual developers all the way to enterprise organizations with the most demanding agentic use cases."
§4.2 · Tone by context
ContextRegisterPrinciple
Landing page heroSharp, declarative, 8 secondsLead with capability, not belief. Compounding = structural fact.
Docs / READMEFunctional, peer-levelNo preamble. Every sentence answers: what does this do, how do I use it, what breaks.
GitHub DiscussionsColleague on SlackOne or two sentences is right. Acknowledge the attempt before redirecting.
UI microcopyFunctional, minimalState what happened, not what to feel. Empty states describe the next concrete action.
SocialTerse, observation-firstLead with recognition, not announcement. Earn the link with the post.
Conference stageCredibility-first, show then tellOpen with a problem the audience has experienced. Show a system working before explaining why.
§4.3 · The 10 writing rules (distilled)
#RuleReason
R-01Talk about agents as systems, not actorsDescribe what they do structurally. Avoid implying cognition / intent / learning.
R-02Open source as infrastructure, not ideologyStructural choice with structural consequences, not a value statement.
R-03Democratization without the VC framing"Democratize" signals pitch deck. Name who benefits and what they can do.
R-0450-person org frame: use it without arroganceStructural (gap narrows), not a claim of equivalence.
R-05Technical claims need a mechanismSuperlatives with no mechanism signal the writer doesn't know how it works.
R-06Don't explain what a builder already knowsThe reader builds agents. Every line of context-setting costs trust.
R-07Compounding is structural, not motivationalProperty of modular architecture — not community spirit.
R-08Own = forkable + no hidden layersDescribe properties: forkable, self-hostable, no telemetry, no vendor lock-in.
R-09One idea per sentence in key positionsReaders scan first. Hero + key headings.
R-10If you can't cut the word, the sentence is wrong"Essentially," "comprehensive," "seamlessly" are symptoms.
§4.4 · Vocabulary — use / avoid
Use — preferredWhy
FoundationsStructural, not metaphorical. Something you build on.
PrimitivesThe brand term. Precise, developer-native, no ideological weight.
ComposablePrecise technical term. Modularity + interoperability.
HarnessSpecific to agentic infrastructure — wires things, manages lifecycle.
OrchestrateCoordinates agents, routes tasks, manages dependencies.
CompoundCore structural claim. Verb or adjective — never noun.
ForkableMore concrete than "open" — implies you can take it and run it.
Pre-wiredConnections exist, scaffolding is done. You don't start from zero.
Operating layerThe category definition.
YoursOwnership claim, personal. Not "owned by you" — "yours."
Avoid — bannedWhy
Seamless / seamlessly integrateThe worst two-word combination in software marketing. Claims experience, not mechanism.
Powerful / robustContent-free. Every product claims this. Describe what it does.
Leverage (verb)Corporate-speak for "use" or "build on."
UnlockLazy verb. Use a specific verb instead.
Next-gen / cutting-edge / AI-nativeTime-stamped, content-free, or overloaded.
Intelligent / magic / magicalAnthropomorphizing. Opposite of inspectable.
Automate (as promise)"Automate your workflow" erases the builder. Use "orchestrate."
Scale (as noun) / platformVC vocabulary / overloaded. Use "layer," "foundation," "infrastructure."
EmpowerPositions user as passive. Inverts the actual relationship.
Disruptive / revolutionaryStartup-era. Signals a company performing innovation.
Commons is contribution-only. Valid in contribution / OSS context — "contributors add to the commons." Do not use as the brand category descriptor; use "primitives" instead.
