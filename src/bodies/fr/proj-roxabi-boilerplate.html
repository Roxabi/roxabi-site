01

Ce que c'est

Construire un produit SaaS de zéro impose de câbler la même infrastructure à chaque fois — auth, multi-tenancy, clés d'API, permissions, email, CI, documentation — avant d'écrire la moindre ligne de ce qui rend ton produit unique. roxabi-boilerplate livre tout ça prêt pour la production, pour qu'une équipe démarre à sa première vraie fonctionnalité plutôt qu'à sa dixième brique de plomberie.

Il associe un monorepo TypeScript moderne à une équipe d'agents IA intégrée pour tout le cycle — triage d'issues, implémentation, revue de code, déploiement. La plomberie est faite ; le workflow vient avec.

La valeur, c'est tout ce que tu n'écris pas. Auth, tenancy et CI sont des problèmes résolus — les voici, résolus, pour que ton premier commit soit du produit.

02

La stack

Un monorepo TurboRepo orchestre trois apps au-dessus de packages partagés, donc seul ce qui change se reconstruit. Les choix sont délibérément actuels et stricts — Bun pour la vitesse, Biome pour un lint-et-format unique et rapide, TypeScript en mode strict partout.

CoucheTechnologie
MonorepoBun + TurboRepo · graphe de tâches + cache de build
LangageTypeScript 5.x, strict
FrontendTanStack Start (SSR) — web
BackendNestJS + Fastify — api
DocsFumadocs + Next.js — docs
OutillageBiome (lint + format) · Vitest + Playwright · Lefthook

Les packages partagés — ui, types, config, email — sont consommés à travers les apps via les workspaces Bun, donc un contrat ou un composant se définit une fois et se réutilise partout.

03

Ce qui est déjà câblé

L'infrastructure dont la plupart des produits SaaS ont besoin dès le premier jour, présente et testée avant que tu ne commences.

  • Auth sans mot de passe — magic-link par email via better-auth, sessions sécurisées côté serveur.
  • Multi-tenancy — des organisations où tu invites, entre lesquelles tu bascules, que tu gères.
  • RBAC — contrôle d'accès par rôle, à l'échelle de l'organisation.
  • Clés d'API — émission et révocation par organisation.
  • Email — avec templates, dans son propre package partagé.
  • Gates qualité — hooks Lefthook (commit-msg, pre-commit, pre-push) et release sémantique : Conventional Commits → changelog + tags.
04

Une équipe IA intégrée

Le boilerplate est livré avec une équipe d'agents Claude configurée pour tout le cycle de dev — le même workflow roxabi-plugins sur lequel tourne le reste du portfolio. Une issue passe du triage à l'implémentation, la revue et le merge le long d'un chemin défini, avec les git hooks et la CI comme garde-fous.

GitHub Issue → Branche → Implémenter → PR → Revue → Merge

Ce n'est pas un ajout greffé. Les agents, les docs de standards qu'ils lisent et le pipeline qu'ils suivent font partie du repo — clone-le et le workflow est déjà là.

05

Lance-le

Prérequis : Node ≥ 24, Bun 1.3.9+, et Docker pour la base de données. L'installation amène les git hooks avec elle ; une seule commande lève chaque app.

bun install
bun run db:up && bun run db:migrate && bun run db:seed
bun run dev          # web :3000 · api :4000 · email :3001

Apps, packages partagés, site de docs et bibliothèque de standards complète sont tous en accès ouvert.
